## Разработка и деплой

```bash
npm ci
npm run dev        # http://localhost:4321
npm run build      # статика в dist/
npm run preview    # предпросмотр собранного dist/
npx astro check    # типы + шаблоны (должен быть 0 errors)
```

Деплой: push в `main` → GitHub Actions (`ubuntu-latest`) → GitHub Pages.

### Переменные сборки

| Переменная | Где задаётся | Назначение |
| --- | --- | --- |
| `SITE_URL` | workflow (автоматически) | публичный адрес сайта. Из него берутся canonical, sitemap, `llms.txt`, `robots.txt` и `manifest` |
| `ASTRO_BASE` | workflow (автоматически) | базовый путь, для user-site это `/` |
| `GA_ID` | repo variable | ID счётчика GA4; если пусто — берётся значение по умолчанию из `src/data/site.ts` |
| `YM_ID` | repo variable | ID счётчика Яндекс.Метрики; если пусто — счётчик не подключается вовсе |

Счётчики грузятся **только после согласия** пользователя на аналитику.

### Переход на свой домен

Сайт собран так, что адрес не зашит в код: достаточно задать `SITE_URL`.

> **Важно:** при деплое через GitHub Actions файл `CNAME` **игнорируется**
> (только branch-деплой его читает). Домен прописывается в
> **Settings → Pages → Custom domain**.

Текущий прод: **https://capybaravpn.top/** — старый `capybara-vpn.github.io`
отдаёт 301 на него.

Порядок — именно такой, DNS сначала:

1. В панели DNS-провайдера заменить текущие записи на записи GitHub Pages.
   Для апекс-домена:

   | Тип | Имя | Значение |
   | --- | --- | --- |
   | A | `@` | `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153` |
   | AAAA | `@` | `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153` |
   | CNAME | `www` | `capybara-vpn.github.io` |

   Старую запись провайдера (у Namecheap это парковочная A-запись) удалить.
2. Дождаться, что домен резолвится в эти IP. **Только после этого** переходить
   к шагу 3: если домен прописать в Pages раньше, старый адрес начнёт отдавать
   301 на нерабочий домен, и сайт ляжет.
3. **Settings → Pages → Custom domain** → вписать домен → Save. GitHub проверит
   домен и выпустит сертификат.
4. Задать repo variable `SITE_URL` = `https://<домен>` — от него тянутся
   canonical, sitemap, `llms.txt`, `robots.txt` и `manifest`. Либо оставить
   пустым: тогда workflow подставит origin из `actions/configure-pages`, он
   учитывает кастомный домен.
5. Включить **Enforce HTTPS** (доступно после выпуска сертификата, до 24 ч).
6. Проверить: canonical, `sitemap-0.xml`, `robots.txt`, `llms.txt`,
   `manifest.webmanifest` содержат новый адрес; старый `capybara-vpn.github.io`
   отдаёт 301 на новый домен.
7. Добавить новый домен в Вебмастер/Бинг/GSC и переобход страниц.

#### Ускорение распространения

NS-записи кешируются резолверами на срок TTL из реестра, и смена делегации
растягивается на часы. Практически: после переключения Namecheap → Cloudflare
часть резолверов (Google, Cloudflare) до суток отдаёт старый IP, и часть
трафика попадёт на страницу хостера. Ускорить нельзя — устаревшая запись лежит
в кеше резолвера, а не в зоне.

Чтобы не словить это на запуске, перед сменой NS стоит **заранее** снизить TTL
в старой зоне до 300 с и подождать сутки, а после переключения вернуть 3600 с.
