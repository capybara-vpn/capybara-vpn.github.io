# Аудит capybaravpn.top — 21.10.2026

Методика: разбор всех 53 файлов `src/`, `npm run build`, `npx astro check`, axe-core 4.10.2
(6 страниц × desktop/mobile), Chromium 1440/1920/1024/768/412/390/360/320 с троттлингом
CPU×4 + 1.6 Мбит/150 мс, живой краул прода (23 URL), анализ доменов бренда и конкурентов,
GEO-структура (llms.txt / .md / JSON-LD).

Итог: техника сделана грамотно (перф, a11y-контраст, JSON-LD — выше среднего), но **сайт
сейчас не может получить масштабный РФ-трафик**, потому что обрублен от канала бренда,
сидит на «спамовой» зоне и не имеет юридического каркаса. Ниже — по приоритету.

## P0 — блокеры

### P0-1. Сайт не связан с собственным Telegram-каналом бренда; воронка обрывается
- **Доказательство:** `t.me/s/capybara_vpn_store` (последний пост 03.10.2026) содержит
  **18 упоминаний `capybaravpn.app`**, **6 упоминаний `capybara.black`** и
  **0 упоминаний `capybaravpn.top`**. При этом `capybaravpn.app` отдаёт `301 → https://capybara.black/`
  (то есть сразу в приложение), а `capybaravpn.top` в канале не упоминается ни разу.
- **Итог:** главный актив бренда (канал) не приводит на лендинг вообще. Кнопка «🌐 Сайт»
  в каждом посте ведёт в личный кабинет, минуя SEO-страницу. Ноль бэклинков с самого
  авторитетного ресурса, который у бренда есть.
- **Фикс:** в шапке/описании канала и в каждом новом посте — `https://capybaravpn.top/`.
  Плюс: `capybaravpn.app` должен 301-ить на лендинг (а не на приложение), иначе
  исторический трафик и ссылки уйдут мимо.

### P0-2. Домен `.top` для коммерческого РФ-проекта — плюс домен не тот
- **Доказательство:** `capybaravpn.top` → GitHub Pages (A-записи GitHub, без истории).
  Бренд уже владеет `capybaravpn.app` (HSTS-preload зона `.app`), `capybaravpn.com`
  (→ 301 на `capybaravpn.pro`) и `capybara.black` (приложение).
  У `capybaravpn.pro` — **индексируемая история**: `sitemap.xml` → `static_pages.xml`,
  `category_pages.xml`, `news_pages.xml`; в выдаче — страницы-локации (`vpn-finland.html`),
  база знаний `capybaravpn.pro/help.html`, отзывы, «О компании».
- **Итог:** `.top` — дешёвая new-gTLD зона, годами скупалась под спам. Яндекс по умолчанию
  привязывает `.ru`/`.рф` к России, `.top` — нет. Хуже проходит фильтры доверия, хуже
  воспринимается пользователем → бьёт по поведенческим и коммерческим факторам.
  Одновременно бренд **выбрасывает накопленный траст** `.com`/`.pro` в сторону.
- **Фикс:** основной домен — `capybaravpn.ru` (или `.рф`), `capybaravpn.top` → 301 на него.
  `capybaravpn.app` и `capybaravpn.com` → 301 на новый основной.
  Если `.ru` недоступен — как минимум `capybaravpn.app` → 301 → `capybaravpn.top`
  (это переносит и ссылочный вес, и трафик).

### P0-3. Ноль юридических страниц — для РФ это потолок коммерческой выдачи
- **Доказательство:** в `src/pages/` нет ни `oferta`, ни `privacy`, ни `contacts`, ни `refund`.
  В футере (`Footer.astro`) — только копирайт и ссылки на разделы.
- **Итог:** оферта обязательна для подписки конечному потребителю (ст. 437 ГК РФ);
  ФЗ «О рекламе» ст. 18 требует идентифицируемого рекламодателя; 152-ФЗ требует политику
  обработки ПДн (сайт грузит GA4/Метрику, бот собирает платёжные данные). Яндекс в
  коммерческом ранжировании и фильтрах качества режет сайты без обратной связи и реквизитов
  (его чек-лист «доверие/прозрачность»), Google — в Quality Rater Guidelines («E-E-A-T,
  Who, How, Why»). Плюс: без реквизитов не запустить ни рекламу, ни партнёрку.
- **Фикс:** `/oferta/`, `/privacy/` (ПДн + cookie), `/contacts/` (реквизиты, e-mail,
  юр. лицо, адрес), `/refund/`. Ссылки в футере + в панели согласия. В JSON-LD:
  `Organization.contactPoint`, `address`, `legalName`.

### P0-4. На 320px первый экран без CTA, и он перекрыт баннером согласия
- **Доказательство (замер, 320×568):** header = 147 px; consent-bar = `top 514, h 54`;
  hero-кнопки Telegram/Браузер = `y 557/558` → **целиком ниже первого экрана и перекрыты
  баннером** (`heroCtaBlocked: true`). Скриншот: видно полосу-объявление, шапку, поднав,
  бейдж, H1 и обрезанный на полуслове абзац. Ни одной кнопки.
- **Второе:** на 768 px пунктирные орбиты пересекают карточку «КАНАЛЫ» (визуальный дефект).
  Третье: на десктопе **LCP-элементом является текст cookie-баннера**, а его кнопка
  «Разрешить» использует `.btn-primary` — тот же бирюзовый градиент, что у главного CTA.
  Cookie-запрос визуально выглядит как главная кнопка конверсии.
- **Фикс:** (1) убрать мобильный поднав (дублирует футер) или заменить на «← На главную»;
  (2) сжать строку объявления до одной строки; (3) на ≤360 px уменьшить H1 до 34–36 px и
  переставить порядок: CTA → лид; (4) consent-бар сделать ненавязчивым (не `.btn-primary`)
  или показывать после 2 c / по скроллу; (5) поправить `overflow`/z-index орбит на 768.

## P1 — высокий приоритет

### P1-1. Яндекс.Метрика не подключена
- **Доказательство:** живой HTML — `<html lang="ru" data-ga-id="G-FHS5BR8L5J" data-ym-id>`
  (атрибут **пустой**). `YM_ID` не задан → загрузчик метрики не подключается вообще.
- **Итог:** для РФ это главный инструмент: без него нет поведенческих данных, которые
  нужны для оптимизации коммерческих запросов и для проверки гипотез по CTR.
- **Фикс:** создать счётчик в Метрике → repo variable `YM_ID`. (Код готов, включается автоматически.)

### P1-2. Сайт не добавлен в Яндекс.Вебмастер / Bing Webmaster, нет региональной привязки
- В `robots.txt` нет **яндекс-специфичной директивы `Host:`** (объявление канонического хоста).
  Есть только `yandex-verification` meta на главной (это ок).
  IndexNow-ключ и POST есть — это единственный кусок из «Вебмастер-механики», который работает.
- **Фикс:** добавить в Вебмастер Яндекса и Bing, регион = Россия, загрузить
  `sitemap-index.xml`, добавить `Host: capybaravpn.top` в robots.txt.

### P1-3. H1 главной не содержит ключевого слова; H2 секций — тоже
- **Доказательство:** `<title>` = «Capybara VPN — быстрый VPN от 249 ₽ для всех устройств»,
  а `<h1>` = **«Интернет — без лишней суеты»**. Ни одного «VPN» в H1.
  H2 секций: «Спокойный сервис для быстрого интернета», «VPN не должен быть второй работой»,
  «Выберите свой ритм», «Вопросы и честные ответы», «Подключение за несколько шагов» —
  ни один не содержит коммерческий интент («тарифы», «цена», «купить», «подключить VPN»).
  На гайдах H1 нормальные — проблема только на главной.
- **Итог:** Яндекс и Google сопоставляют запрос с H1/title. Слоган в H1 не даёт релевантности
  по «vpn от 249 рублей», «купить vpn», «тарифы vpn».
- **Фикс:** H1 = «Capybara VPN — быстрый VPN от 249 ₽», слоган — подзаголовком/lead.
  H2 секций переписать под интент: «Тарифы Capybara VPN: 30, 90 и 180 дней»,
  «Как подключить VPN за 3 шага», «Почему Capybara VPN», «Частые вопросы о VPN».
  Добавить ключ в первые 100 слов (`lead`).

### P1-4. Бренд противоречит сам себе: цифры на этом сайте ≠ цифры на индексируемых доменах бренда
- Здесь: **38 локаций, 100+ серверов, 1 устройство, 249 ₽ / 30 дней**.
  `capybaravpn.pro` (в выдаче): **810 серверов, 21 страна, 180 ₽/мес, «6 рублей в сутки»**.
  Teletype (индексирован 05.2026): Capybara — **810+ серверов, 21 страна, 569 ₽/мес за 5 устройств**.
- **Итог:** поисковик видит три разных «Capybara VPN» с разными ценами и разным парком
  серверов → размывается сущность бренда, сниппет может быть собран с `.pro`.
  Это конфликт, который напрямую режет коммерческие запросы.
- **Фикс:** выбрать один источник правды по цифрам и вычистить остальные домены
  (301 на канонический + правка контента). Заодно решить, сколько локаций/устройств реально.

### P1-5. `/official/` утверждает, что официальный адрес — `capybaravpn.top`, а канал говорит `capybaravpn.app`
- **Доказательство:** `official.astro:37` и `:107` — «Официальный адрес один: capybaravpn.top».
  В канале — 18× `capybaravpn.app` → 301 на `capybara.black`.
- **Итог:** пользователь из канала попадает на `capybara.black` и видит «официальный сайт»
  в другом месте; доверие падает, поведенческие факторы ухудшаются.
- **Фикс:** привести к одному адресу (см. P0-1/P0-2) и синхронизировать текст страницы.

### P1-6. `.md`-версии страниц индексируемы и дублируют HTML
- **Доказательство:** живой `GET /ios.md` → `200`, `content-type: text/markdown`.
  В sitemap их нет, `noindex` у них нет, canonical у них нет → Google может заиндексировать
  как дубли `/ios/`.
- **Фикс:** в `robots.txt` запретить `.md` **только для Googlebot/Bingbot**,
  оставив доступ всем AI-краулерам:
  ```
  User-agent: Googlebot
  Disallow: /*.md$
  User-agent: Bingbot
  Disallow: /*.md$
  ```
  (Порядок блоков в robots.txt значим — специфичные правила должны идти до `User-agent: *`.)

### P1-7. «Не сейчас» в cookie-баннере навсегда отключает аналитику
- **Доказательство:** `site.ts:297` `declineConsent()` → `writeStoredConsent('denied')` +
  TTL 180 дней. Эту функцию зовут и кнопка «Не сейчас», и клик мимо, и Esc.
- **Итог:** пользователь, который нажал «не сейчас» (= «потом»), на 6 месяцев выпадает из
  Метрики/GA4. При потоке из Telegram это **тысячи потерянных визитов без данных**.
- **Фикс:** разделить «dismiss» (не писать в localStorage, спросить позже) и «decline»
  (явный отказ). Esc и клик мимо → dismiss.

### P1-8. Все тарифные CTA ведут на один общий URL — выбранный план теряется
- **Доказательство:** `Pricing.astro` — три кнопки «Подключить» → `site.browserUrl` без
  параметра тарифа; `data-tariff` уходит только в аналитику.
- **Итог:** клик по «180 дней — 1195 ₽» приводит на общую страницу приложения, где план
  надо выбирать заново — самая дорогая точка потери конверсии на коммерческой странице.
- **Фикс:** deep-link с тарифом (`?plan=180d` или `start`-payload Telegram-бота на каждый
  тариф), если приложение умеет; иначе — текст кнопки с тарифом + редирект.

### P1-9. Нет продуктовой разметки с ценой; `FAQPage` на 23 страницах без пользы для сниппетов
- **Доказательство:** на каждой странице `Service` + `SoftwareApplication` + `FAQPage`.
  Google с 2023 не показывает FAQ-сниппеты коммерческим сайтам; `Service`/`SoftwareApplication`
  не дают price-rich-result. Цена есть только в `hasOfferCatalog`.
- **Фикс:** `Product` (или `Service` + прямой `offers`) с `offers.price/priceCurrency/availability/
  priceValidUntil`, `aggregateRating`/`review` — **только когда есть реальные отзывы** (выдуманные
  нарушают политику Google и ФЗ «О рекламе»).

### P1-10. У гайдов нет автора, нет видимой даты обновления, а `dateModified` — hardcode
- **Доказательство:** `dateModified: '2026-10-21'` зашит в каждом `.astro` (напр. `ios.astro:24`).
  При правке текста дата **не поменяется** — сигнал свежести станет ложным. На странице нет
  ни строки «Обновлено», ни автора. `author` = `Organization` безPerson.
- **Итог:** GEO-практики (Princeton/KDD): атрибуция эксперта +25–30%, свежесть — отдельный
  фактор; Яндекс тоже смотрит на «кто за этим стоит». Сейчас страница выглядит анонимно-конвейерной.
- **Фикс:** считать `dateModified` из git (в `astro.config.mjs` это уже делается для sitemap —
  переиспользовать), выводить видимое «Обновлено 21 октября 2026» + блок автора
  (`Person` с описанием компетенций), `datePublished`/`dateModified` — из данных страницы.

## P2 — средний

### P2-1. Два места с битыми ссылками при деплое в подпапку (base path)
- **Доказательство (сборка с `ASTRO_BASE=/capybara/`):** в HTML появились
  `href="/android/"` и `href="/ios/"` — без префикса, тогда как всё остальное корректно
  (`/capybara/ios/`).
  Источники: `Related.astro:31` (`href={g.href}`) и `Platforms.astro:58` (`href={g.href}`) —
  забыли `withBase`.
  Второе: `manifest.webmanifest.ts` — иконки `"/icon-192.png"`, `"/icon-512.png"`,
  `"/icon-512-maskable.png"` без base → **битые PWA-иконки** на subpath-деплое.
- **Фикс:** `href={withBase(g.href)}` в обоих файлах; иконки манифеста — `withBase(...)`.

### P2-2. На 404 мёртвая ссылка «наверх»
- **Доказательство:** `404.astro` не оборачивает контент в `<div id="top">` (0 совпадений
  в `dist/404.html`), а `Footer.astro` содержит `href="#top"` (совпадение есть).
  На 404 клик по логотипу футера ничего не делает.
- **Фикс:** обернуть 404 в `<div id="top">` (как `index.astro` и `GuideLayout.astro`) или
  заменить ссылку на `withBase('/')`.

### P2-3. Битый HTML-атрибут `alt` у логотипов
- **Доказательство:** `dist/index.html` → `<img src="/logo-96.png" alt width="96" height="96" ...>`.
  `Logo.astro` по умолчанию `alt=''`, и Astro выдаёт **пустой boolean-атрибут** — невалидный HTML.
  `site.logo.alt` ('логотип капибары') используется только в `FinalCta`.
- **Итог:** невалидная разметка; логотип без alt-пробы для поиска по картинкам и для сущности бренда.
- **Фикс:** в `Logo.astro` не подставлять `alt` вообще при пустом значении (пусть будет `alt=""`),
  а для логотипа в шапке/футере дать осмысленный alt (ссылка уже имеет `aria-label` — тогда
  корректнее `alt=""`, но атрибут должен быть валидным).

### P2-4. Мобильный поднав занимает 40 px и на 23 из 24 страниц ведёт на главную
- Header на мобильном = 147 px: 33 (объявление) + ~74 (лого+кнопка) + ~40 (поднав).
  На гайд-страницах все 4 пункта поднава (`/#pricing`, `/#benefits`, `/#how`, `/#faq`)
  уводят на главную — это шум и лишний вес перед H1.
- **Фикс:** на гайдах поднав заменить на «← На главную» + текущий раздел; на главной —
  оставить, но задать `py-2.5` (минимум 44 px по WCAG 2.5.8).

### P2-5. Тап-таргеты меньше 24 px (WCAG 2.2 AA 2.5.8)
- **Доказательство (замер):** чипы платформ «iOS/Android/Windows/macOS/Linux/TV» — **20 px**
  высотой (`Platforms.astro`, ссылки `g.short`); кнопка «Тарифы» в шапке — 35 px;
  ссылки мобильного поднава — 35 px; ссылки футера — 29 px; лого+ссылка шапки — 36 px.
  20 px — ниже порога 24 px (WCAG 2.2 AA).
- **Фикс:** чипам платформ дать `py-1.5` (→ 28+ px), поднаву `py-2.5`, кнопке шапки `py-2.5`.

### P2-6. axe: `landmark-complementary-is-top-level` (moderate) на всех 20 гайд-страницах
- Блок «Коротко» — это `<aside>` внутри `<article>` внутри `<main>`; axe считает, что
  complementary-landmark не должен быть вложен в другой landmark.
- **Фикс:** `<aside>` → `<div role="note">` или вынести из `<article>`.

### P2-7. Нет security-заголовков на проде
- **Доказательство (заголовки живого ответа):** нет `strict-transport-security`,
  `x-content-type-options`, `referrer-policy` (только `<meta>`), `x-frame-options`,
  `permissions-policy`. `http→https` и `www→non-www` отдают 301 (Enforce HTTPS включён),
  но HSTS-заголовка нет.
- **Фикс:** включить «Enforce HTTPS» в Pages Settings (GitHub добавляет HSTS для custom-доменов)
  либо поставить Cloudflare перед GitHub Pages (но осторожно — Cloudflare ломает автопродление
  сертификата Pages; тогда сертификат перестаёт быть GitHub-овым).

### P2-8. `deploy.yml` хардкодит домен в шаге IndexNow
- **Доказательство:** `ORIGIN="https://capybaravpn.top"`, `host: "capybaravpn.top"` —
  захардкожено, хотя `SITE_URL`/`steps.pages.outputs.origin` уже есть. При смене домена
  (а он сменится, см. P0-2) IndexNow будет уведомлять не тот хост, и шаг упадёт молча
  (`continue-on-error: true`).
- **Фикс:** использовать `steps.pages.outputs.origin`. Заодно добавить в workflow шаг
  `npx astro check` (см. P0-5).

### P2-9. `robots.txt`: нет `Host:` (яндекс-директива) и нет `Disallow` для `/404.html`
- `/404.html` отдаётся с `noindex` и исключён из sitemap — это ок. Но `Host:` для Яндекса
  не задан (низкий приоритет, поведение директивы надо перепроверить в текущей справке).

### P2-10. `<meta name="keywords">` — мёртвый тег
- `BaseLayout.astro:166` — Яндекс и Google его не учитывают. Не вредит, но это шум и
  дублирование списка тем (убедиться, что он не противоречит H1/description после правок).

### P2-11. `link rel="describedby" href=".../llms.txt"` — некорректное применение отношения
- `describedby` означает «документ, описывающий этот документ». Указание на `llms.txt` —
  семантическая ошибка. Рядом уже есть корректный `<link rel="alternate" type="text/plain">`.

### P2-12. `/pricing.md` не виден человеку
- На него ссылается только `llms.txt`. Добавить видимую ссылку в футер или в `/tarify/`.

### P2-13. `.md`-версии собираются регексом по HTML — качество страдает
- `astro.config.mjs:107` `htmlToMarkdown()`: `<li>` → `- $1` без вложенности,
  `<td>` → ` | $1` **без строки-разделителя таблицы** (Markdown-таблица получается битой),
  SVG вырезается целиком, `<a href>` теряет саму ссылку (остаётся только текст).
- **Итог:** агент, читающий `.md`, получает огрызки — ровно то, что нужно для цитирования.
- **Фикс:** генерировать markdown из исходников Astro (frontmatter + слот), а не из
  отрендеренного HTML.

### P2-14. Орбиты перекрывают карточку «КАНАЛЫ» на 768 px
- Визуальный дефект (скриншот): пунктирная окружность проходит сквозь подпись карточки.
- **Фикс:** обрезать орбиты контейнером (`overflow: hidden` на визуальной части) или

### P2-15. Hero-иллюстрация занимает ~450 px и не несёт информации

- **Фикс (дизайн):** на ≤1023 px убрать орбиты и плавающие чипы, оставить логотип 160 px;
